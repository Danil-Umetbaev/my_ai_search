# Локальная проверка агента

Исходник: https://github.com/koyotixe/smart-agent
Импортирован commit 0c05cd7fc5f5b8b7bd4fe8748188e47397bfbf77.
Это самостоятельный стенд в папке smart-agent, без интеграции в основную админку.
Исходные тесты поставщика сохранены как часть репозитория.

## Быстрый режим

Из PowerShell:

```powershell
cd C:\Users\user\my_ai_search\smart-agent
$compose = @('-f', 'docker-compose.yml', '-f', 'docker-compose.support.yml', '-f', 'docker-compose.trial.yml')
docker compose @compose up -d --build
docker compose @compose logs --tail=60 app
```

Локальный .env уже подготовлен при импорте и исключён из Git. Для нового клона
скопируйте .env.example в .env, задайте POSTGRES_PASSWORD и случайный JWT_SECRET_KEY.
Не копируйте настройки основной базы. Trial override задаёт отдельное имя проекта,
образы, кеш, базу и порт. Нужен Docker Compose с поддержкой !reset и !override.

Откройте http://localhost:18082. Первая сборка скачает зависимости и базовые образы;
модели и CUDA в этом режиме не скачиваются. Повторный запуск без изменений:

```powershell
docker compose @compose up -d
```

## Что проверить

1. Зарегистрируйтесь, откройте «Техподдержка».
2. Напишите «У меня ничего не работает». Проверьте уточнения.
3. Начните новый диалог: «На кассе 2 не печатается чек, перезапуск не помог».
   Проверьте, учитываются ли уже сообщённые сведения.
4. Ответьте «не знаю», затем «Нужен специалист». Исправьте сводку:
   «окружение: касса 3». Подтвердите заявку.
5. Обновите страницу: история и заявка должны сохраниться.
6. В новом диалоге проверьте «отмена» и «проблема решена»: заявка не должна создаваться.
7. Создайте второго пользователя и назначьте его специалистом:

```powershell
docker compose @compose exec app python -m src.support_admin --email support@example.com --role it
```

Подставьте зарегистрированный email. Выйдите и войдите этим пользователем,
откройте панель специалиста, возьмите заявку в работу, заполните решение и закройте.
Проверьте результат под первым пользователем.

## Ограничения проверки

Этот режим проверяет резервный сценарий на правилах, сохранение диалога и заявки.
LLM отключена, база знаний новая и пустая. Качество нейросетевого агента и поиска
этот прогон не доказывает. Полный режим описан в HANDOFF.md; для него нужны модели,
GPU и отдельное наполнение базы. При полном запуске также используйте trial override
последним файлом, чтобы сохранить изоляцию от основного проекта.

Остановка без удаления данных:

```powershell
docker compose @compose stop
```
