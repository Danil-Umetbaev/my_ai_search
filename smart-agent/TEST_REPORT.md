# Проверка примера агента поддержки

Проверено 4 ноября 2026 года в Docker с PostgreSQL 16/pgvector.
Ни один тест агента не требует скачивания моделей или доступа к GPU.

## Результаты

- Целевой набор агента и health API: **35 passed**.
- Общий набор `backend/tests`: **39 passed, 2 failed**.
- `npm run build`: успешно, сборка React/Vite для production.
- Лёгкий образ `Dockerfile.support`: успешно собран без PyTorch/CUDA.
- Конфигурация `docker-compose.support.yml`: проверена через `config --quiet`.
- Миграции с нуля до `support_workflow_02`: успешно применены к отдельной БД.
- Откат `support_workflow_02 → support_agent_01` и повторное применение: успешно.
- Отдельный лёгкий стенд запускается; страница входа открывается.
- `git diff --check`: без ошибок пробелов.

Два сбоя общего набора относятся к прежним тестам VK-эскалации:
`test_chat_escalated` и `test_chat_escalated_when_notification_fails`.
Они ожидают `escalated`, тогда как существующий ChatService возвращает `not_found`
и сообщает результат доставки уведомления текстом. Это отдельный старый модуль,
а не новые заявки поддержки. Код старого поиска и ожидания этих тестов не менялись.

Целевой набор проверяет:

- вопросы по разным типам неисправности и пропуск уже известных данных;
- переход с правил на план LLM и сохранение истории;
- запрет выдуманных фактов и цитат, повторных вопросов и проверок;
- резервный путь при таймауте, неправильном JSON и сбое поиска;
- отмену и явное подтверждение решения;
- регистрацию, вход, Origin и разграничение доступа;
- повторную отправку с request_id и конфликт другого содержимого;
- конкурентные сообщения без перезаписывания истории;
- создание заявки только после подтверждения;
- назначения, решение, версии и журнал действий специалиста;
- получение пользователем своих заявок и решения.

## Что не следует считать проверенным

LLM в автоматических тестах заменена управляемым планировщиком. Качество реальной
Qwen и полноту найденных инструкций программист проверяет на своём сервере и базе.
Это проверка интеграции и переходов, не доказательство точности любых диагнозов.

Ручной сквозной просмотр панели специалиста не завершён: автоматическая проверка
разрешений отклонила создание отдельной тестовой учётной записи с ролью it.
Соответствующие операции и ограничения проверены API-тестами в отдельной тестовой БД.
