# Процедуры печати чеков: каталог и выбор в диагностике

Версия 2026-11-09.2. Основание — [аудит 27 случаев](RECEIPT_COVERAGE.md). Источник данных — [receipt_procedures.json](receipt_procedures.json). На шаге 5 каталог подключён к диагностике. Структура БД, документы и индекс не изменены.

## Что означает готовность

`ready` — последовательность проверена по сохранённому источнику и выполнима при всех указанных условиях. Это не испытание на физической кассе и не гарантия устранения любой неисправности. Проверка связи и получение отчёта остаются диагностикой.

`needs_specialist_review` — требуется решение специалиста; `blocked_missing_materials` — отсутствует обязательная часть инструкции. Обе категории запрещены к выдаче в качестве готовых шагов. Приведённые в них шаги — черновик для редактора.

Каталог: `ready` — 12, `blocked_missing_materials` — 5, `needs_specialist_review` — 7. Все 27 исходных случаев сопоставлены с процедурами или явным пробелом.

## Правила исполнителя

1. Выбрать кандидатов по карточке случая; затем проверить ВСЕ условия `applicability.all_of`. `equals` сравнивает значение и тип; `one_of` допускает перечисленные значения. Отсутствующее значение и «не знаю» не означают `false`.
2. Задавать вопросы только о недостающих фактах. `required_before_steps` отличает обязательное условие от полезного уточнения. Физический рулон, индикатор и текст ошибки хранить отдельно. При противоречии — уточнить.
3. Проверить статус, отпечатки источников и доступность обязательных материалов. Для фотографий/схем показать нужную страницу до выполнения шагов; если она не открывается, не выдавать инструкцию как готовую.
4. Не объединять последовательности из разных процедур. Не переносить настройку одной модели на другую. Для семейных проверок Вики допустим `model=Вики Принт`; отдельные модельные инструкции требуют точной модели.
5. Сохранять результат и уже выполненные действия. Не повторять неудачную процедуру без новых фактов. Диагностический отчёт и успешная связь не завершают обращение как решённое.
6. Только подтверждение пользователя завершает проблему. При неудаче или нехватке знаний предложить специалиста; создавать заявку после согласия. Не запрашивать фиктивную продажу для проверки печати.

Ограничения из источника находятся в `documentation_restrictions`. Правила продукта — в `product_limits` и `selection_contract`; они не выдаются за текст производителя. Сейчас сервисные проверки разрешены только серверным ролям `admin`/`it`. Эту политику нужно согласовать с заказчиком перед промышленным запуском.

## Пробелы, которые нельзя скрывать общей инструкцией

Все подробности — в `coverage` JSON и исходном аудите. Особенно:

- АТОЛ: нет готовой проверки датчика при установленном рулоне, настройки яркости, QR-восстановления. Замятие и перекос сейчас описаны как готовые варианты только для горизонтальной установки 80 мм.

## Шаг 5: выбор процедуры и поиск

`SupportDialogueService` вызывает `SupportKnowledgeService`. Сбор фактов остаётся в
`receipt_facts`, вопросы и переходы — в `receipt_diagnosis`. Выбор и проверка данных
каталога — в `receipt_procedures`. Запрос активных документов принадлежит
`DocumentRepository`; SQL и инструкции не смешаны с переходами диалога.

- В `routing` каталога заданы намерения, уточнения и варианты кнопок. Условия,
  шаги, ограничения и ссылки берутся из одной процедуры, без склейки вариантов.
- Перед выдачей проверяются статус `ready`, модель, все условия, отпечатки
  актуальных документов и наличие обязательных PDF. Изменённый или архивный
  источник требует повторной проверки процедуры.
- Кнопки передают типизированное значение текущего факта. Старые кнопки
  отклоняются. Неполное обозначение FPrint-22 не считается подтверждением 22ПТК.
- При смене модели прежние материалы и действие сбрасываются. Уже выполненная
  проверка не повторяется автоматически. Результат связи или отчёт не считаются
  подтверждением исправной печати.
- Если готового сценария нет, `support_retrieval` ищет по активным документам,
  предварительно ограничивая их моделью и известной платформой. Используется
  небольшой лексический поиск на CPU по текущим 196 разделам/статьям. Генерация
  ответа не участвует в выборе источников. Обычный чат с RAG не изменён.
- Дальше передаются до пяти **полных разделов**, включая ограничения. Это
  справочные материалы (`executable=false`), а не разрешение выполнять ремонт.
  Они сохраняются в состоянии диалога, ссылки показываются пользователю.
  Без готовой процедуры предлагается специалист; заявка требует подтверждения.
