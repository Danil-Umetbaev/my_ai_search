# База оборудования клиента

База PostgreSQL: `customer_knowledge`. Старая рабочая база не изменяется.
В этой ветке объединены новая база, авторизация, админка и экспериментальная поддержка.

Загрузка 05.11.2026 завершена: 196 документов (47 HTML-статей, 76 разделов
АТОЛ, 73 страницы Пирит), 1675 активных фрагментов, 788 привязок изображений.
Документов без активного индекса нет. Индексация выполнена на GPU существующей
Qwen3-Embedding-0.6B. Наличие индекса не означает правильность всех ответов RAG.
Дамп: backups/customer_knowledge_20261105.dump в корне проекта, вне Git.
Обновлённый дамп после исправлений: backups/customer_knowledge_quality_20261105.dump.
Сохранённые материалы занимают около 56 МиБ.

Источники перечислены в knowledge_urls.txt: статьи Вики Принт и руководство
АТОЛ FPrint-22ПТК для ПО 5.0. Руководство Пирит 2Ф передаётся локальным PDF.
Evo-tex проверен: опубликованные инструкции относятся преимущественно к Эвотор,
поэтому в этот набор не включены.

Из backend загрузка выполняется так:

```powershell
python -m src.ai.ingestion.customer download --pirit "C:/Users/user/Desktop/Manual_Pirit2F_1_.pdf"
```

Результат — data/knowledge_assets: документы, оригиналы PDF и изображения.
documents.json содержит подготовленные данные; failures.json — ошибки загрузки.
Файлы исключены из Git, но нужны для переноса базы и выдачи иллюстраций.
Нельзя удалять эту папку как временные результаты тестов.

Для индексации настройте подключение к отдельной базе и примените миграции.
Импортёр отказывается писать в базу с другим именем:

```powershell
$env:DB_NAME = "customer_knowledge"
alembic upgrade head
python -m src.ai.ingestion.customer index
```

В базе должны быть включены расширение vector и миграции этой ветки.
Повторный запуск пропускает неизменившиеся документы. Каждый документ и его
индекс записываются одной транзакцией. Ошибка останавливает индексацию;
после исправления её можно продолжить той же командой.

Оригиналы PDF сохраняются целиком. При наличии закладок страницы объединяются
в разделы, иначе индексируются постранично. Пустые страницы без текста и растровых картинок
пропускаются. Для АТОЛ версия 5.0 взята из руководства; неизвестные версии и
точные модели Вики Принт не угадываются. Перед фильтрацией по конкретной модели
нужно разметить применимость общих статей семейства Вики Принт.

Изображения связаны с документом через images: исходный URL, локальный путь,
подпись, позиция и страница PDF. Одинаковые файлы хранятся по хешу.
Растровые изображения извлекаются из PDF; векторные схемы сохраняются в оригинале
PDF. Содержимое картинок не распознаётся OCR/VLM и не превращается в инструкции.
Ссылки на изображения хранятся отдельно от текста, чтобы служебные маркеры
не попадали в ответы.

API `/api/v1/knowledge-assets/{filename}` выдаёт картинки и оригиналы PDF.
Для работы API папка data/knowledge_assets должна присутствовать в backend.
Отрисовка картинок в ответах чата и выбор подходящей иллюстрации ещё не подключены.

## Запуск приложения с этой базой

Все команды выполняются из корня репозитория. В `.env` задайте
`APP_DB_NAME=customer_knowledge`. `POSTGRES_DB` остаётся именем старой базы:
её не переименовываем и не удаляем. Миграция `customer_application_01`
объединяет таблицы оборудования, админки и поддержки. На старте backend
сам выполняет `alembic upgrade head`.

На подготовленном компьютере достаточно:

```powershell
docker compose up -d --no-build
```

Откройте http://localhost:18081 (порт задаётся `HTTP_PORT` в `.env`).
Первый запуск моделей занимает время. Состояние видно в `/api/v1/health`:
`models: ready` означает, что поиск готов. До этого чат возвращает 503.

На новом компьютере:

1. Скопируйте `.env.example` в `.env` и заполните пароли и настройки.
2. Получите дамп базы и папку `backend/data/knowledge_assets` у разработчика.
   В Git нет базы, моделей и загруженных документов.
3. Поднимите PostgreSQL: `docker compose up -d db`. Создайте в нём базу
   `customer_knowledge` и восстановите дамп через `pg_restore`.
4. Уберите локальное значение `BACKEND_IMAGE`, если оно есть. Соберите приложение:
   `docker compose up -d --build`. Для GPU нужен NVIDIA Container Toolkit;
   на Windows — Docker Desktop с WSL2 и поддержкой GPU.
5. Для первой учётной записи зарегистрируйтесь в интерфейсе. Назначить администратора:
   `docker compose exec app python -m src.support_admin --email YOUR_EMAIL --role admin`.
   После смены роли войдите заново.

Создание и восстановление базы на новом компьютере (только в пустую базу):

```powershell
docker compose up -d db
docker compose exec db sh -c 'createdb -U "$POSTGRES_USER" customer_knowledge'
docker compose cp ./backups/customer_knowledge_quality_20261105.dump db:/tmp/customer.dump
docker compose exec db sh -c 'pg_restore -U "$POSTGRES_USER" -d customer_knowledge --no-owner --no-acl /tmp/customer.dump'
docker compose up -d --build
```

После восстановления дампа более старой версии приложение само применит
недостающие миграции. Не запускайте восстановление поверх заполненной базы.
Для отдельного окружения задайте `VITE_KNOWLEDGE_SPACE` при сборке фронтенда:
оно отделяет локальную историю браузера от других баз. По умолчанию используется
`customer-knowledge`.

`BACKEND_IMAGE` — необязательное переопределение образа backend. На текущем
ноутбуке используется `my_ai_search_backend:customer-local`: сохранённый локальный
образ с уже установленными зависимостями. Другому разработчику этот образ не нужен.
Два существующих пользователя перенесены в новую базу на этом ноутбуке.
Старые чаты и заявки намеренно остались в старой базе.

## Где менять код

- `api/v1` принимает HTTP-запросы и переводит ошибки сервисов в HTTP-ответы.
- `services` содержит сценарии работы; `repositories` — запросы к БД.
- `services/rag.py` выполняет поиск, ранжирование и подготовку контекста.
- `ai/evidence.py` отбирает фрагменты; `ai/llm/qwen.py` обращается к модели.
- `services/admin.py` сохраняет документы и запускает переиндексацию.
- `services/support_agent.py` — отдельный экспериментальный сценарий диагностики.
  Обычный чат использует RAG напрямую, без обязательных уточнений агента.

Импорт по URL в админке пока поддерживает прежний Confluence-источник.
Загрузка текущих Dreamkas/PDF выполняется командой ingestion выше; редактирование,
архивация и переиндексация уже загруженных документов доступны в админке.

Изображения доступны по ссылкам, но модель не распознаёт их содержимое.
Если инструкция ссылается на выделенную кнопку на картинке, откройте оригинал.

## Быстро обновить код без пересборки

```powershell
docker compose cp ./backend/src/. app:/backend/src/
docker compose exec app alembic upgrade head
docker compose restart app
npm --prefix frontend run build
docker compose cp ./frontend/dist/. frontend:/usr/share/nginx/html/
docker compose restart frontend
```

Копирование действует до пересоздания контейнера. Для постоянного развёртывания
соберите образ из актуального кода. При смене `APP_DB_NAME` нужен
`docker compose up -d --no-build --force-recreate app`, а не только restart.
Не направляйте новую версию на старую базу для отката без согласования миграций:
откат приложения включает подходящую версию кода и сохранённую старую базу.
