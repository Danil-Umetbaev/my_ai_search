# База оборудования клиента

База PostgreSQL: `customer_knowledge`. Старая рабочая база не изменяется.
Ветка основана на main с последующим обновлением из origin/main.

Загрузка 05.11.2026 завершена: 196 документов (47 HTML-статей, 76 разделов
АТОЛ, 73 страницы Пирит), 1675 активных фрагментов, 788 привязок изображений.
Документов без активного индекса нет. Индексация выполнена на GPU существующей
Qwen3-Embedding-0.6B. Наличие индекса не означает правильность всех ответов RAG.
Дамп: backups/customer_knowledge_20261105.dump в корне проекта, вне Git.
Обновлённый дамп после исправлений: backups/customer_knowledge_quality_20261105.dump.
Сохранённые материалы занимают около 56 МиБ.

Источники перечислены в knowledge_urls.txt: статьи Вики Принт и руководство
АТОЛ FPrint-22ПТК для ПО 5.0. Руководство Пирит 2Ф передаётся локальным PDF.
Evo-tex проверен: опубликованные инструкции относятся преимущественно к Эвотор,
поэтому в этот набор не включены.

Из backend загрузка выполняется так:

```powershell
python -m src.ai.ingestion.customer download --pirit "C:/Users/user/Desktop/Manual_Pirit2F_1_.pdf"
```

Результат — data/knowledge_assets: документы, оригиналы PDF и изображения.
documents.json содержит подготовленные данные; failures.json — ошибки загрузки.
Файлы исключены из Git, но нужны для переноса базы и выдачи иллюстраций.
Нельзя удалять эту папку как временные результаты тестов.

Для индексации настройте подключение к отдельной базе и примените миграции.
Импортёр отказывается писать в базу с другим именем:

```powershell
$env:DB_NAME = "customer_knowledge"
alembic upgrade head
python -m src.ai.ingestion.customer index
```

В базе должны быть включены расширение vector и миграции этой ветки.
Повторный запуск пропускает неизменившиеся документы. Каждый документ и его
индекс записываются одной транзакцией. Ошибка останавливает индексацию;
после исправления её можно продолжить той же командой.

Оригиналы PDF сохраняются целиком. При наличии закладок страницы объединяются
в разделы, иначе индексируются постранично. Пустые страницы без текста и растровых картинок
пропускаются. Для АТОЛ версия 5.0 взята из руководства; неизвестные версии и
точные модели Вики Принт не угадываются. Перед фильтрацией по конкретной модели
нужно разметить применимость общих статей семейства Вики Принт.

Изображения связаны с документом через images: исходный URL, локальный путь,
подпись, позиция и страница PDF. Одинаковые файлы хранятся по хешу.
Растровые изображения извлекаются из PDF; векторные схемы сохраняются в оригинале
PDF. Содержимое картинок не распознаётся OCR/VLM и не превращается в инструкции.
Ссылки на изображения хранятся отдельно от текста, чтобы служебные маркеры
не попадали в ответы.

API `/api/v1/knowledge-assets/{filename}` выдаёт картинки и оригиналы PDF.
Для работы API папка data/knowledge_assets должна присутствовать в backend.
Отрисовка картинок в ответах чата и выбор подходящей иллюстрации ещё не подключены.

Не переключайте запущенное приложение агента на эту базу простой заменой DB_NAME:
в ней миграции main, а у ветки агента дополнительно есть таблицы поддержки и админки.
Перед объединением нужно согласовать ветки миграций и развернуть соответствующий код.

## Проверка RAG 05.11.2026

Проверены 18 вопросов: 11 с ответом в документах, 3 без достаточных сведений,
4 вне тематики. Все 18 статусов совпали с ожидаемыми. Это проверка небольшого
набора, а не оценка точности на всей базе; правильный статус сам по себе
не подтверждает полноту ответа.

Проверка содержания подтвердила восстановление четырёх шагов замены бумаги
Пирит, порядка шагов заправки АТОЛ и сноски об опциональных беспроводных
интерфейсах. Из ответа о подключении Вики Принт убрана инструкция для двух касс.
Поиск по словам теперь учитывает русские словоформы средствами PostgreSQL.

На том же наборе медиана 11 ответов снизилась с 15,8 до 12,0 секунды;
8 из 11 уложились в 15 секунд. Диапазон последнего прогона: 7,7–48,1 секунды.
Скорость зависит от прогрева и загрузки ноутбука; гарантии 15 секунд нет.
В отдельной проверке один и тот же вопрос о печати Вики Принт занял
37,9 секунды первым запросом после загрузки моделей и 11,5 секунды повторно.

Остаются длинные ответы, подписи рисунков и отдельные номера элементов схем
в извлечённом PDF-тексте. Изображения сохранены, но их содержание модель
не анализирует. Для вопросов с недостаточными данными эта ветка возвращает
отказ, а не проводит диагностику и не угадывает неисправность.
